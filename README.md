# ШоуБум — сайт услуг аниматоров

Учебный проект по предметной области **«Услуги аниматоров»**: сайт агентства детских праздников с каталогом программ и аниматоров, оформлением заказов, отзывами, личными кабинетами и административной панелью.

Сайт переведён со статических HTML-страниц на динамические PHP-страницы с общей базой данных MySQL/MariaDB. Подключён API **DaData** (подсказки и нормализация контактных данных).

---

## 1. Возможности

### Публичная часть
- **Главная** — программы праздников, преимущества, отзывы, призыв к заказу.
- **Аниматоры** — каталог с фильтрами:
  - по специализации;
  - по возрастной группе;
  - по программе;
  - по свободной дате и времени;
  - по цене и имени.
- **Карточка аниматора** — фото, опыт, ставка, программы, отзывы, кнопка заказа.
- **Цены** — программы и стоимость, дополнительные услуги.
- **Заказ** — форма бронирования с проверкой занятости аниматора и расчётом стоимости.
- **Отзывы** — опубликованные отзывы клиентов.
- **Контакты** — контактная информация, карта, форма обращения.
- **Авторизация / регистрация** — вход по email или телефону, регистрация заказчика и аниматора.
- **Личный кабинет** — отдельный интерфейс для каждой роли.

### Личный кабинет заказчика
- список заказов со статусами;
- отмена заказа;
- отзыв после завершённого заказа;
- загрузка и удаление фотографий с праздников;
- редактирование профиля и смена пароля.

### Личный кабинет аниматора
- входящие заявки: подтверждение, отклонение, завершение;
- календарь занятости по месяцам;
- бронирования на текущую неделю;
- портфолио (загрузка/удаление фото);
- выбор специализации, возрастных групп и программ;
- редактирование профиля и ставки.

### Административная панель (`/admin/`)
- сводка по базе;
- CRUD для всех 10 таблиц:
  `users`, `animators`, `age_groups`, `animator_age_groups`, `programs`,
  `animator_programs`, `bookings`, `reviews`, `photos`, `contact_requests`;
- просмотр 5 представлений (VIEW) — готовых запросов из задания.

## 3. Установка

### Вариант А. Через установщик (рекомендуется)

1. Скопируйте папку проекта в каталог сайтов, например:
   `C:\OSPanel\domains\shouboom`
2. Запустите **Apache** и **MySQL/MariaDB**.
3. Убедитесь, что домен `shouboom` указывает на локальный сервер. В OSPanel запись в `hosts` создаётся автоматически; если браузер пишет «Сервер не найден», добавьте в `C:\Windows\System32\drivers\etc\hosts` строку:
   ```
   127.0.0.1 shouboom
   ```
4. Откройте в браузере:
   `http://shouboom/install.php`
   (или `http://localhost/install.php`, если папка называется иначе).
5. Нажмите **«Установить базу данных»**.
   Установщик создаст базу `Услуги аниматоров`, таблицы, 5 представлений и демонстрационные данные.
6. Перейдите на главную страницу сайта.

### Вариант Б. Импорт через phpMyAdmin

1. Создайте базу с именем `Услуги аниматоров` (кодировка `utf8mb4`).
2. Импортируйте файл `database.sql`.
3. Проверьте настройки подключения в `config.php`.

### Настройки подключения

Файл `config.php`:

```php
define('DB_HOST', '127.0.0.1');
define('DB_NAME', 'Услуги аниматоров');
define('DB_USER', 'root');
define('DB_PASS', '');
```

Значения можно переопределить переменными окружения:
`SHOUBOOM_DB_HOST`, `SHOUBOOM_DB_NAME`, `SHOUBOOM_DB_USER`, `SHOUBOOM_DB_PASS`.

В репозиторий файл `config.php` не попадает (он в `.gitignore`), так как содержит
секреты. После клонирования создайте его из шаблона:

```bash
copy config.example.php config.php
```

и впишите свои данные подключения и токены DaData.

## 5. Подключение API DaData

DaData используется для подсказок и нормализации:
- адресов;
- ФИО;
- телефонов;
- email.

### Архитектура

Браузер **не** обращается к DaData напрямую. Запросы идут на серверный прокси:

```
assets/app.js  →  api/dadata.php  →  https://dadata.ru
```

Токены и секрет хранятся только на сервере в `config.php` и не попадают в HTML/JavaScript.

### Эндпоинты прокси

| Запрос | Назначение |
|--------|-----------|
| `api/dadata.php?action=status` | Проверка доступности сервисов |
| `api/dadata.php?action=suggest&type=address&query=Твер` | Подсказки адреса |
| `api/dadata.php?action=suggest&type=fio&query=Иван` | Подсказки ФИО |
| `api/dadata.php?action=suggest&type=email&query=test` | Подсказки email |
| `api/dadata.php?action=clean&type=phone&value=8 916 123-45-67` | Нормализация телефона |
| `api/dadata.php?action=clean&type=email&value=TEST@MAIL.RU` | Нормализация email |
| `api/dadata.php?action=clean&type=name&value=иван иванов` | Нормализация ФИО |
| `api/dadata.php?action=clean&type=address&value=...` | Нормализация адреса |

### Токены DaData

В `config.php` используются два токена (у токенов DaData набор функций может отличаться):

```php
define('DADATA_TOKEN', '6e0a…c07');        // подсказки (SUGGESTIONS)
define('DADATA_CLEAN_TOKEN', '18ef…7f9');  // нормализация (CLEAN)
define('DADATA_SECRET', '1a89…7bc');       // секрет для cleaner
```

- **подсказки** идут через `DADATA_TOKEN`;
- **нормализация** — через `DADATA_CLEAN_TOKEN` + `DADATA_SECRET`.

Обе функции проверены и работают. Если для какого-то токена функция отключена,
код автоматически переключается на локальный справочник / локальную нормализацию,
поэтому формы не ломаются. При наличии одного токена с обоими функциями
можно указать его в обоих параметрах.

### Проверка API

```bash
curl "http://shouboom/api/dadata.php?action=status"
curl "http://shouboom/api/dadata.php?action=suggest&type=address&query=%D0%9C%D0%BE%D1%81%D0%BA%D0%B2%D0%B0"
curl "http://shouboom/api/dadata.php?action=clean&type=phone&value=8%20916%20123-45-67"
```

Ожидаемый ответ `status` при работающих обоих сервисах:

```json
{"ok":true,"suggestions_available":true,"cleaner":true,"message":"DaData: подсказки и нормализация доступны."}
```

## 8. Безопасность и валидация

- PDO с **подготовленными запросами** (защита от SQL-инъекций);
- **CSRF-токены** на всех POST-формах;
- пароли хранятся через `password_hash()` (bcrypt);
- проверка ролей: `require_login()`, `require_admin()`;
- серверная валидация:
  - обязательные поля;
  - формат email (`FILTER_VALIDATE_EMAIL`);
  - телефон — 11 цифр;
  - пароль — не менее 6 символов;
  - дата заказа — не в прошлом;
  - проверка пересечения бронирований;
- загрузка изображений: проверка типа, размера и расширения;
- экранирование вывода через `e()` (`htmlspecialchars`);
- запрет листинга каталогов в `.htaccess`.

## 10. Примечания

- Демонстрационные данные можно восстановить, удалив базу и заново открыв `install.php`.
- Для повторной установки без удаления базы используйте импорт `database.sql` в пустую базу.
- Если сайт открывается по адресу вида `http://localhost/шоубум/`, все ссылки относительные и работают без настройки `base_url`.
- Для продакшена рекомендуется сменить пароли демо-аккаунтов, токены DaData и включить HTTPS.

## 11. Публикация проекта на GitHub

### 1. Подготовка Git

Установите Git (https://git-scm.com/download/win) и проверьте:

```bash
git --version
```

Укажите имя и email, которые будут видны в коммитах:

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "you@example.com"
```

### 2. Инициализация репозитория

Откройте терминал в папке проекта и выполните:

```bash
git init
git add .
git commit -m "Initial commit: сайт ШоуБум"
git branch -M main
```

`config.php` в коммит не попадёт — он исключён через `.gitignore`, потому что
содержит токены DaData и пароль базы. В репозиторий попадает только
`config.example.php`.

### 3. Создание репозитория на GitHub

1. Войдите на https://github.com.
2. Нажмите **New repository**.
3. Введите имя, например `shouboom`.
4. Выберите **Public** или **Private**.
5. **Не** добавляйте README, `.gitignore` и лицензию — они уже есть в проекте.
6. Нажмите **Create repository**.

### 4. Привязка и отправка

Скопируйте ссылку на репозиторий и выполните (замените `USERNAME`):

```bash
git remote add origin https://github.com/USERNAME/shouboom.git
git push -u origin main
```

При запросе пароля GitHub не принимает обычный пароль аккаунта. Нужен
**Personal Access Token**: GitHub → Settings → Developer settings →
Personal access tokens → Tokens (classic) → Generate new token, права `repo`.
В качестве пароля вставьте этот токен.

Альтернативы: GitHub Desktop или GitHub CLI (`gh auth login`, затем
`gh repo create`).

### 5. Проверка

Обновите страницу репозитория — файлы, README.md и история коммитов должны
отображаться на GitHub. Дальнейшие изменения:

```bash
git add .
git commit -m "Описание изменений"
git push
```

> **Важно:** не коммитьте `config.php` с реальными токенами. Если секреты уже
> попали в историю, смените токены в личном кабинете DaData и удалите файл из
> истории (`git filter-repo` или новый репозиторий).
